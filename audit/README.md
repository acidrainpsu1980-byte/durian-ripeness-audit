# Audit package index (v1.9.1)

Where each artifact requested in review is, how it was produced, and how it is checked. Every file below is regenerated by
`run_all.sh` (or the named script) and compared with the shipped copy; see `../REPRODUCE.md`.

## 1. Recording exclusions with the evidence for each

| File | Content |
|---|---|
| `exclusion_ledger.csv` | One row per excluded unit with `level`, `reason_code`, `evidence`, `evidence_source`, `effect`: 4,227 archive members not read (2,348 `__MACOSX` resource forks, 4 archive metadata tables, 1,467 thermal/RGB captures named with field tree codes and no fruit number, 408 captures of fruits outside the analysis set), 25 fruits, 47 sessions without all four sensors (excluded from evaluation; their captures stay in training folds), 106 knock recordings |
| `../data/raw_file_inventory.csv` | Every member of the four Zenodo archives (12,328 rows) with size, CRC-32 from the zip directory, parsed fruit id and its role in the analysis (`src/audit/inventory_raw.py`, needs the archives) |
| `../data/sound_recording_manifest.csv` (Table S7) | The 562 knock recordings: MD5, size, source original, file-system timestamp, matched session and date, byte-identical copies, status and the evidence for the decision |
| `../data/sound_session_evidence.csv` (Table S8) | Per session (269): iPhone and Android files, originals, observed dates and status, inter-device offset |
| `../data/sound_exclude_wrong_session.txt` | The 106 excluded Android recordings; 105 are byte-identical (MD5) to the same fruit's other-session file, 1 is excluded on its timestamp alone |
| `fruits.csv` | All 189 fruits: analysis status, reason for exclusion, fruit-linked captures per sensor, stratum and folds in p0–p9 |

## 2. Session identifiers, label decisions and the ten fruit partitions

| File | Content |
|---|---|
| `sessions.csv` | The 315 sessions (`session_id` = `<fruit_id>_<date>`) of the 164 analysis fruits: per-sensor file-name labels, the common label, its basis (unanimous file label, or the fruit-log rule applied), log-inconsistency flag, fruit-log dates, captures per sensor, `in_evaluation_268`, sound evidence, and the fold in each partition |
| `../data/session_labels_common.csv` (Table S10) | The adjudicated common session label with the rule applied |
| `fruit_partitions.csv` (= `../src/nested_selection/partitions.csv`) | 164 fruits × 10 stratified 5-fold fruit partitions; `p0` is the frozen primary split (seed 42), `p1`–`p9` seeds 1–9 |
| `table1_dataset_structure.csv` | Table 1 recomputed from the files above (`src/audit/table1.py`) |

## 3. Candidate models, hyper-parameter searches, software versions and training settings

| File | Content |
|---|---|
| `model_registry.csv` | The 21 classical candidates and the knock CNN: feature set and dimension, preprocessing, estimator, every fixed hyper-parameter, the searched grid, inner CV (GroupKFold by fruit, macro-F1), seed, aggregation, fits per partition; generated from the estimator objects in `src/nested_selection/cands.py` |
| `configuration_space.csv` | The 26 configurations of the nested configuration search (C26) and the 11 stacking configurations added in C37 |
| `hyperparameter_search_p0.csv` | Every grid point of every grid-searched candidate on each outer fold of p0 (370 rows): per-split inner scores, mean, rank, chosen point; the refitted searches reproduce the shipped outer predictions exactly |
| `predictions/selection_choices.csv` (Table S12) | Every inner score and every family / configuration choice of the selection procedures, per partition and fold |
| `SOFTWARE.md`, `requirements_lock_cpu.txt`, `../environment.yml` | CPU and GPU software stacks, exact package versions, thread settings |
| `../models/primary_p0/` | Fitted models of the four development pipelines on the primary partition, one per outer fold (15 scikit-learn pipelines, 5 knock-CNN state dicts with their normalisation constants), with `model_check.csv` |

## 4. Out-of-fold predictions and scripts that reproduce the principal tables

| File | Content |
|---|---|
| `predictions/capture_oof.parquet` | Capture / recording-level outer-fold probabilities of every base candidate in every partition (p0cpu = primary partition with the CPU knock CNN; p0–p9 with the GPU refits): 358,633 rows |
| `predictions/session_oof.parquet` | Session-level outer-fold probabilities on the 268 evaluation sessions for every base candidate and every configuration and selection procedure (64 per partition, 11 partitions): 188,672 rows; recomputing the fold metrics from it reproduces `results/v14/partition_per_fold.csv` exactly |
| `predictions/session_oof_primary.csv` | The same for the primary partition, human-readable |
| `supplementary/TableS1…S22_*.csv` | Supplementary Tables S1–S22 regenerated from the result files (S6–S20 are byte-identical to the submitted files except S14, whose role label and two column names were changed in v1.9.1; S21–S22 added in v1.9.0) |
| `../results/v17/matched_space_session_oof.parquet` | v1.9.0: session-level outer-fold probabilities of every development pipeline, selection procedure and fixed-configuration fusion of Table 3, 11 partitions (written by `matched_space.py`) |
| `../results/v19/` | v1.9.0 (`src/nested_selection/primary_metric.py`): `estimates_by_partition.csv` (fold-mean and pooled macro-F1 / accuracy and pooled class recall per estimate and partition), `estimates_summary.csv` (Table 3, S21), `comparisons_macro_f1.csv` (Table 4, S22) |
| `table_map.csv` | For every table and figure: source files, script and `run_all.sh` stage |
| `manuscript_number_check.csv` | Every three-decimal number in Tables 3–12, and every one- and two-decimal number in Tables 3–4 (1,101 in total), occurs in the result files mapped to its table (`src/audit/check_manuscript_numbers.py`) |

## 5. Commands from raw data and from cached features
